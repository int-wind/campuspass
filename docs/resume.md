CampusPass 校园活动报名平台｜开发时间：2026.10.20–2026.10.21｜主要负责人：本人
技术栈：Java 21、Spring Boot 2.7.18、Spring Security、MyBatis-Plus、MySQL 8、Redis 7、RabbitMQ 4、Spring AMQP、Caffeine、Flyway、Sentinel、JMeter

项目简介：面向高校讲座、社团活动等免费活动的报名场景，针对热门活动集中报名时名额易超发、候补递补依赖人工、报名确认与现场核销流程分散的问题，开发了覆盖活动发布、限额报名、候补递补、确认和核销的后端系统。

- 针对热点场次报名与详情查询的高延迟，引入 Outbox＋RabbitMQ 异步受理和 Redis＋Caffeine 两级缓存。本机真实依赖、100 并发对照压测中，报名申请受理 P95 从 1,707ms 降至 84ms，活动详情 P95 从 927ms 降至 110ms。
- 针对抢名额超额、重复报名及候补乱序，使用 Redis Lua 原子预占和幂等校验，并以 MySQL 条件更新、容量流水和递增序号保证最终名额与候补顺序。6 人并发争抢 1 个名额时，结果为 1 人待确认、5 人候补且位置依次为 1–5；30 分钟持续测试提交 10,000 次模拟申请，1,000 名额场次未超额，容量流水与占用数一致。
- 针对服务中断可能造成的请求丢失和账目不一致，使用 MySQL Outbox 持久化报名意图、RabbitMQ 确认与重试、消费者手动 ACK 及 Redis 预占租约。真实故障注入中，Broker 和 Redis 重启后请求完成处理；消费者强制终止时消息从 `unacked=1` 回到 `ready=1`，重启后报名成功；MySQL 写入失败时名额占用与流水均为 0，解除故障后的单名额报名两者均为 1。
- 针对 Refresh Token 重放和退出后会话残留，采用 15 分钟 JWT Access Token、7 天随机 Refresh Token、Redis 散列存储与 Lua 原子轮换，并在每次鉴权时检查会话状态。8 个并发刷新请求中仅 1 个成功；注销后使用旧 Access Token 请求返回 401。

测试说明：以上数据来自本机单实例和模拟账号、活动；100 并发时 202 受理速率为 31.5→28.1 次/秒，不能据此声称报名完成吞吐提升。200 并发出现 JDBC 连接池超时，未纳入正式对照；尚未采集逐请求报名完成耗时、缓存命中率和数据库回源次数。
